# Проверка Kafka Workbench 1.0.0

Дата: 7 октября 2026 года. Этот документ разделяет выполненные проверки и ограничения результата. Наличие исходников теста или workflow не считается успешным запуском.

После удаления лишней надписи над заголовком инцидентов повторно выполнены production build и сценарий прохождения всех шести инцидентов: 1 pass. Это изменение не затрагивает движок и сервер.

## Что доказывают тесты

- 18 уроков имеют уникальные идентификаторы, содержательную структуру, две проверки, объяснения и официальные источники. Сервер не отдаёт ключи ответов в API курса.
- Открытие урока и неверные ответы не дают завершение. Две успешные проверки дают один результат, повторные попытки сохраняются. Последняя ошибка не стирает ранее достигнутое освоение.
- SQLite сохраняет ответы, заметки и историю инцидента после закрытия и нового открытия базы. Миграция с первой схемы не теряет ранее сохранённый прогресс.
- Два наблюдения обязательны для диагноза. Неверные гипотезы и исправления не завершают ни один из шести кейсов. Уменьшение lag переводом offset в конец не засчитывается как восстановление; удаление истории требует начать кейс заново; idempotent producer не исправляет внешние платежи.
- API отвергает поддельные действия, лишние поля, большие тела, недопустимые Origin и Host. Лабораторные команды имеют фиксированный набор аргументов и не выполняются через shell. Стенд другого checkout не изменяется.
- Визуальная модель проверяет независимость consumer groups, локальность offset внутри partition, redelivery до commit, продолжение с committed offset и незанятых потребителей при избытке членов группы.
- В браузере проверены ошибка ответа с повтором, обе проверки урока, заметка, перезагрузка, экспорт, поиск без результатов, недоступный Docker, ошибка сети и повторное подключение.
- Проверена гонка: ответ удерживается в сети, пользователь переходит к сбросу, сброс ждёт завершения ответа. После сброса API и перезагрузка показывают пустой прогресс.
- Все шесть инцидентов завершены через интерфейс и сохранены после reload. Проверены неверная гипотеза, опасное исправление, отдельная верификация, предыдущий кадр, воспроизведение, пауза, reduced motion и отмена сброса.

## Реальный Kafka, не модель

Live-тест использует отдельный Compose project `kafka-workbench-lab-test` и настоящий образ `apache/kafka:4.2.2`.

1. Дождался ответа metadata и проверил три партиции учебного topic.
2. Повторное создание topic не привело к потере данных или ошибочному дублированию.
3. Проверил начальную сумму end offsets 0, записал три заказа с ключами и проверил сумму 3. Распределение в проверенном запуске: `2 / 1 / 0`.
4. Прочитал ровно три ожидаемые записи, проверил содержимое и committed offsets `2 / 1 / 0` группы `workbench` с lag 0.
5. Повторное чтение вернуло 0 записей. Пустой результат принят только после проверки доступных metadata и нулевого lag.
6. Завершил стенд. Дополнительно через Docker проверены отсутствие тестовых контейнеров, сети и всех трёх захваченных anonymous volume IDs.

Повторный прогон выявил ошибку на кириллическом пути: UTF-8 мог разделиться между блоками stdout Docker и повредить проверку принадлежности checkout. Исправлено потоковым StringDecoder отдельно для stdout/stderr. Регрессионный тест передаёт кириллицу побайтово. Приведённые выше успешные результаты получены после исправления.

Дополнительно проверены заполненная песочница, мобильный главный экран, клавиатурный skip link, закрытие меню по Escape и отсутствие горизонтального переполнения на 375, 390, 800 и 1440 px в описанных браузерных сценариях.

Это автоматическая проверка выбранных состояний, а не сертификат WCAG и не полный аудит со screen reader. [Сравнение концепта с интерфейсом](DESIGN-QA.md) описывает отдельную визуальную проверку.

## Ограничения

Один доверенный локальный пользователь, одна SQLite-база на установку. Нет проверенной многопользовательской изоляции, публичного хостинга или нагрузочных гарантий. Один реальный брокер не доказывает высокую доступность и восстановление реплик. Модель не исполняет реальные сетевые таймеры и протоколы Kafka. macOS отдельно не проверялся. Не проводились пользовательское исследование, внешний аудит безопасности и сертификация доступности.
