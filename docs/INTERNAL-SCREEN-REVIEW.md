# Внутренние экраны Dark Stream Gallery

Этап 2026-11-12, дополнение пользователя: переработать весь интерфейс под окно, включая внутренние состояния. Инвентарь составлен до дополнительной реализации, по маршрутам и двум независимым ревью кода. Первоначальные дефекты ниже не являются результатами браузерных измерений.

| Маршрут / состояние      | Обнаруженный пробел                                                        | Решение для рабочей компоновки                                                                               |
| ------------------------ | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `#curriculum`            | Каталог не показывает краткий итог главы                                   | Нумерованные главы, прогресс и суммарная длительность, двухколоночная композиция desktop                     |
| `#lesson/<id>`, теория   | На средней ширине справка выглядит продолжением статьи                     | Отдельная матовая справочная панель, ограниченная ширина чтения                                              |
| Урок, тест               | Две проверки стоят длинной лентой, индекс имеет низкий контраст            | Два рабочих листа рядом desktop, последовательность mobile, читаемый индекс и обратная связь                 |
| Урок, заметки            | Сохранение и счётчик разнесены                                             | Единая поверхность тетради с нижней панелью сохранения и состояния                                           |
| `#sandbox`               | Формы, действия и сцена стоят далеко друг от друга                         | Панель управления рядом со сценой desktop; журнал и результат ниже; последовательность на узком экране       |
| `#incidents`, выбор      | Шесть случаев идут перед рабочим сценарием одной колонкой                  | Компактный индекс, согласованный размер названий, без микротекста                                            |
| Инцидент, расследование  | Решение находится после сцены, метрик и истории; мобильные подписи 8-11 px | Наблюдение и решение в рабочих колонках на широком экране; мобильные метрики в двух колонках, текст 12-14 px |
| `#lab/<task>`, редактор  | Полная сцена стоит перед редактором и действиями                           | Единый рабочий разворот решения, запуска и наблюдения; графитовый редактор с высотой по окну                 |
| Практикум, выбор задачи  | URL не отражает выбранную карточку                                         | Синхронизация адреса без потери локальных черновиков при переключении                                        |
| Практикум, подтверждение | Prepare показывает подтверждение в самом низу после журнала                | Подтверждение рядом с действием и перенос фокуса; отмена возвращает фокус                                    |
| Практикум, evidence      | JSON использует двухколоночный стиль карточек модели                       | Самостоятельный моноширинный блок на всю ширину, ограниченный внутренний scroll                              |
| Причинная практика       | Неподдерживаемая consume-кнопка видна в новых задачах                      | Только предусмотренные операции, явное отделение модели и настоящего стенда                                  |
| Базовая лаборатория      | Вывод на мобильном находится после всей инструкции                         | Явный переход к выводу рядом с каждым действием, читаемые команды и журнал                                   |
| `#progress`              | Модули и повторение идут одной длинной лентой                              | Основная колонка модулей и отдельная панель повторения desktop, одна колонка mobile                          |
| `#sources`               | Границы модели и источники идут общей длинной лентой                       | Редакционные колонки объяснения и документации, без декоративной 3D-графики                                  |
| Сбросы / меню            | Нужна согласованность с рабочими панелями                                  | Единые предупреждения, доступные кнопки и сохранение существующего управления фокусом                        |

Приёмка должна включать desktop, 768, 390 и 320 px, реальные внутренние состояния, доступность, действия и сохранение прогресса. Итоговые снимки, выполненные проверки и ограничения добавляются после фактической CUA-проверки. Наличие этого плана само по себе не означает завершения.
