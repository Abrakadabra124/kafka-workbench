Общий аппаратный mutex удерживался на протяжении suites. Базовая лаборатория и новый стенд запускались последовательно, в собственных тестовых Compose projects. Проверка владения сверяет путь Compose и имена сервисов до изменения контейнеров.

- Совместный прогон `tests/labs.test.mjs` и `tests/workspace-live.test.mjs`: **14 pass, 0 fail, 0 skip**, 626.3 с. Базовый одноброкерный цикл прошёл за 84.0 с, трёхброкерный suite за 542.2 с.
- **Доставка:** две полные попытки, по три записи в partition 0/1/2. До чтения и commit независимая проверка отказывает в зачёте. После commit: end=1, committed=1, lag=0 для каждой партиции. Новое чтение возвращает 0, повторная проверка остаётся успешной.
- **Повторная доставка:** две попытки. Два чтения без commit возвращают те же partition/offset/key/value. Порядок между разными партициями не считается гарантированным. После явного commit повторы прекращаются.
- **Отказ и восстановление:** две попытки. Broker 3 действительно остановлен, ISR уменьшается с 3 до 2. Запись `acks=all` и чтение продолжаются. До восстановления реплик и commit зачёт не даётся. После запуска broker 3 ISR каждой партиции снова равен 3; независимый consumer подтверждает записи и offsets.
- В конце нового suite проверены **0 тестовых контейнеров, 0 тестовых сетей и удаление 9 захваченных volume IDs**. Чужие контейнеры, сети и volumes не очищались.

Полная структурированная запись: [workspace-live-2026-11-07.json](evidence/workspace-live-2026-11-07.json). Это реальные ответы локальной Kafka, включая отрицательные проверки и восстановленные metadata.

## Ограничения и выпуск

Все три брокера работают на одном компьютере. Проверен отказ одного процесса/контейнера и восстановление реплик, не отказ машины или независимых зон. Сцена показывает датированный снимок Kafka после операции; движение воспроизводит подтверждённое действие, а не непрерывную телеметрию. JSON-рецепт намеренно ограничен записями и параметрами consumer; произвольный пользовательский код не исполняется.

GitHub CI и публикация отмечаются отдельно после завершения соответствующих запусков. Исторические проверки версии 1.0 остаются в [VERIFICATION.md](VERIFICATION.md).
