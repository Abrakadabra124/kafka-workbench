# Динамическая пространственная визуализация

Требование пользователя от 2026-10-29: улучшить графику Kafka Workbench, сделать профессиональные motion-анимации и динамический 3D-дизайн; применить этот стандарт ко всем тренажёрам проекта. Общая инструкция закреплена в родительском `AGENTS.md`, конкретная реализация описана здесь.

## Визуальная система

Референс: `design/spatial-concept.png`. Светлая рабочая поверхность, графитовый текст Inter, тёплые оранжевые события, белые объёмные станции, стальные боковые грани, мягкие контактные тени и холодные индикаторы. Боковая навигация, учебный маршрут и содержание курса сохраняют существующую структуру.

- Базовый текст: #172031; вторичный: #58647a; границы: #e3e7ed.
- Акцент для текста: #b83316; основной CTA: #d33e1d; цвет события: #f0532b.
- Шкала отступов: 4, 8, 12, 16, 24, 32, 40, 48 px. Контролы 12-14 px, основной текст 14-17 px.
- Геометрия: реальная CSS 3D-сцена с отдельными гранями, перспективой и переключением на плоский вид. Текстовые подписи и управление остаются в обычной плоскости.
- Переходы интерфейса: 160-240 ms для отклика; камера плавно меняет проекцию. Непрерывное движение допустимо только в явно обозначенной демонстрации или во время воспроизведения истории.

Изображение используется как проектный референс, не как интерфейс. Существующие точные названия уроков, сведения о прогрессе и учебные ограничения имеют приоритет над сгенерированным текстом концепта. Схематическая CSS-геометрия нужна для управления каждым элементом и отражения состояния без графической зависимости и внешних запросов.

## Поведение

1. Обзор: демонстрационный поток producer -> три партиции -> consumer. Пауза и переключение проекции доступны с клавиатуры. Демонстрация не изменяет прогресс или учебные данные.
2. Песочница: визуализация получает реальные длины партиций, позиции чтения, commit и владельцев из существующей модели. Запись отмечает выбранную партицию, чтение только полученные записи, commit только сохранение позиции. Перезапуск не создаёт событий. Смена группы и сброс отменяют старую активность.
3. Инциденты: состояние компонентов, ISR, lag, потоки и последствия берутся из выбранного кадра истории. Заблокированный участок и участок с нулевой скоростью не показывают успешную доставку. Число неурегулированных дублей отображает накопленный ущерб, не постоянное появление новых дублей.
4. Управление движением: пользовательская пауза, системный reduced motion, видимость вкладки и попадание сцены в экран. При остановке история не перескакивает на кадры, пропущенные в фоне. Ручной выбор кадров доступен всегда.

## Критерии готовности

- Визуальная проверка обзора, песочницы и инцидента в браузере, на десктопе и мобильной ширине.
- Пауза действительно останавливает анимации; reduced motion останавливает и CSS, и автоматические таймеры истории.
- Проекция и движение не влияют на данные, оценки или прогресс; числа совпадают с журналом.
- Нет горизонтальной прокрутки на мобильном экране, перекрытых контролов, ошибок JavaScript или нарушений проверяемых правил доступности.
- Число визуальных объектов ограничено; React не перерисовывается на каждом кадре анимации.
- Успешные TypeScript, сборка, существующие тесты и отдельные браузерные проверки движения. Реальный Docker/Kafka не требуется для изменения только визуального слоя; его повторный запуск не заявляется без отдельной проверки.

## Технические основания

- [MDN: transform-style](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/transform-style): отдельные пространственные грани; свойства, способные сплющить 3D-контекст, не применяются к внутренним контейнерам сцены.
- [MDN: Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API): остановка фонового воспроизведения.
- [MDN: prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/prefers-reduced-motion): статичное представление при системном предпочтении уменьшенного движения.
