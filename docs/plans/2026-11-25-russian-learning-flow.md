Все три настоящих сценария восстановления прошли по два цикла с неправильными решениями, исправлением и повтором. Завершающая проверка ресурсов обнаружила оставшиеся анонимные тома после успешного `compose down --volumes`. Сам по себе exit code 0 оказался недостаточным доказательством очистки. Проверки живого стенда сохраняют диагностический артефакт до финальных утверждений, чтобы результат учебных сценариев и причина ошибки очистки не терялись.

Итог исправлений должен подтверждаться следующим полным CI. Первый неуспешный запуск не считается успешной приёмкой.

После исправления очистки локальный полный набор: 75 тестов пройдено, 0 ошибок, 3 аппаратные проверки пропущены. TypeScript и сборка Vite прошли. ## Исправление адресной очистки

В запуске `45561926512` короткая аппаратная проверка выявила ещё одну причину: обычный JSON-вывод `compose ps` сокращает ID контейнеров, а проверка принадлежности требует полный ID. `owned()` теперь явно передаёт `--no-trunc`; проверки полного состава контейнеров, меток, подключений, чужих ссылок и метаданных томов сохранены. Флаг предусмотрен [официальной документацией Docker Compose, на английском](https://docs.docker.com/reference/cli/docker/compose/ps/).

Тестовый адаптер сокращает ID до 12 символов без флага. Новая регрессия сначала воспроизвела точную ошибку CI, затем прошла после исправления. Локальный полный набор: 90 тестов пройдено, 0 ошибок, 4 проверки настоящего Docker пропущены; TypeScript, production-сборка и форматирование прошли. Независимое ревью не обнаружило замечаний высокого или среднего приоритета.

Изменение опубликовано в коммите `24bac92ea9cf32286ecea57ea5279056738e46a0`. Локальный сервер перезапущен с этим кодом; API отвечает, JS/CSS побайтно совпадают с production-сборкой. Прежние строки answers, notes, incident_states и workspace_states совпали с сохранённым снимком до изменений.

В [запуске 45562825750](https://github.com/Abrakadabra124/kafka-workbench/actions/runs/45562825750) короткая проверка очистки прошла на настоящем Docker: захвачены 3 контейнера и 9 томов, после остановки оставшихся томов нет, повторная остановка успешна. Артефакт `workspace-cleanup-evidence.json` подтвердил исходную причину непосредственно: обычный вывод Compose содержит ID длиной 12 символов, с `--no-trunc` все три ID имеют длину 64.

Набор настоящих сценариев восстановления также прошёл: 4 теста, 0 ошибок, 0 пропусков. В `practice-live-evidence.json` записаны 76 операций, 20 ожидаемых отрицательных и 12 положительных проверок, два цикла каждого сценария. Финальная проверка ресурсов: 0 контейнеров, 0 сетей тестового проекта, все 9 захваченных томов удалены. Это подтверждает фактический результат, а не только успешное завершение команды.
